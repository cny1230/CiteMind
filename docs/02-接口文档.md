# CiteMind · 接口文档

> 版本：v1.0 ｜ 基准：后端 v0.0.1-SNAPSHOT（Spring Boot 3.5 / port 10001）
>
> 在线调试：应用启动后访问 **http://localhost:10001/doc.html**（Knife4j）。
> 本文档与源码骨架的 `@RequestMapping` 注解保持一致；Controller 当前为骨架占位（实现待补充），
> 因此接口形状以本文档 + 前端 `CiteMind-frontend/src/api/*.ts` 为准。

## 0. 通用约定

### 0.1 基础信息

| 项 | 值 |
|---|---|
| Base URL | `http://localhost:10001/api`（生产经网关前缀可能变化） |
| 传输格式 | JSON（UTF-8）；文件上传为 `multipart/form-data`；下载为二进制流 |
| 认证方式 | `Authorization: Bearer <accessToken>`（除 auth 白名单接口） |
| 刷新令牌 | httpOnly Cookie `CITEMIND_REFRESH_TOKEN`（前端不读取、不存储） |
| 时区 | 全部时间字段为 ISO 8601 字符串（UTC） |

### 0.2 统一响应结构 `ApiResponse<T>`

除「0.3 明确标注的裸返回接口」外，所有接口返回：

```json
{ "success": true, "data": { }, "message": null }
```

| 字段 | 类型 | 说明 |
|---|---|---|
| success | boolean | 业务是否成功 |
| data | T \| null | 业务数据 |
| message | string \| null | 失败原因（成功为 null） |

### 0.3 裸返回接口（不走 ApiResponse 包裹）

| 接口 | 返回 |
|---|---|
| `POST /api/qa/ask` | 直接返回 `AskQuestionResponse` |
| `POST /api/qa/stream-ask` | SSE 事件流 |
| `GET /api/assistant/sessions` | 直接返回会话数组 |
| `GET /api/assistant/sessions/{id}` | 直接返回会话详情 |
| `GET /api/assistant/sessions/{id}/context` | 直接返回上下文对象 |
| `GET /api/documents/{id}/download` | 二进制文件流 |

### 0.4 HTTP 状态码与错误语义

| 状态码 | 语义 | 典型场景 |
|---|---|---|
| 200 | 成功（含业务失败：success=false 时看 message） | 参数校验失败、业务规则拒绝 |
| 401 | 未认证 / 会话过期 | 缺失或无效 Access Token；Refresh Token 失效 |
| 403 | 已认证但无权限 | 非群组成员访问群组资源；USER 访问管理接口 |
| 404 | 资源不存在 | 文档/会话/记录 ID 无效 |
| 500 | 服务器内部错误 | message 为通用描述，详情在服务端日志 |

> 前端解包约定见 [04-前后端联调规范](./04-前后端联调规范.md)。

## 1. 认证 · `/api/auth`

### 1.1 登录 `POST /api/auth/login`

请求体：

```json
{ "loginId": "admin", "password": "admin123" }
```

- `loginId`：用户名或邮箱，不区分大小写。

成功响应 `ApiResponse<AuthTokensResponse>`：

```json
{
  "success": true,
  "message": null,
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiJ9...",
    "currentUser": {
      "userId": 1,
      "userCode": "100001",
      "displayName": "系统管理员",
      "systemRole": "ADMIN",
      "mustChangePassword": false
    }
  }
}
```

同时通过 `Set-Cookie: CITEMIND_REFRESH_TOKEN=...; HttpOnly; Path=/api/auth; Max-Age=1209600` 下发刷新令牌。

失败示例：`{ "success": false, "data": null, "message": "用户名或密码错误" }`（HTTP 200，业务失败）。

### 1.2 注册 `POST /api/auth/register`

```json
{ "username": "zhang.san", "email": "zs@example.com", "displayName": "张三", "password": "Str0ng!Pass" }
```

响应：`ApiResponse<null>`；用户名/邮箱重复时 success=false。

### 1.3 刷新令牌 `POST /api/auth/refresh`

无请求体（依赖 httpOnly Cookie）。成功返回与登录相同结构；Cookie 缺失/失效/重放时返回 **HTTP 401**。
每次刷新会**轮换** Refresh Token（旧值作废）。

### 1.4 登出 `POST /api/auth/logout`

吊销当前 Refresh Token 并清除 Cookie。响应 `ApiResponse<null>`。

### 1.5 当前用户 `GET /api/auth/me`

需 Bearer Token。响应 `data` 同登录中的 `currentUser`。

|---|---|---|---|
| GET | `/api/admin/users` | 用户列表 | `AdminUserItem[]` |

## 4. 协作小组 · `/api/groups` & `/api/invitations`

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| GET | `/api/groups/my` | 我的群组聚合（拥有/加入/待处理邀请） | 登录用户 |
| POST | `/api/groups` | 创建群组 `{ "name": "...", "description": "..." }` → data=新群组 ID | 登录用户 |
| POST | `/api/groups/{groupId}/invitations` | 邀请用户 `{ "inviteeUserId": 3 }` → data=邀请 ID | OWNER |
| GET | `/api/groups/invitations/my-sent` | 我发出的邀请列表 | 登录用户 |
| GET | `/api/groups/{groupId}/members` | 成员列表 | 群组成员 |
| DELETE | `/api/groups/{groupId}/members/{userId}` | 移除成员（不能移除自己） | OWNER |
| POST | `/api/groups/{groupId}/leave` | 退出群组（OWNER 不可退出） | MEMBER |
| POST | `/api/groups/join-requests` | 凭编码申请加入 `{ "groupCode": "G-RD-TEAM" }` → data=申请 ID | 登录用户 |
| GET | `/api/groups/join-requests/my` | 我的申请列表 | 登录用户 |
| GET | `/api/groups/{groupId}/join-requests` | 群组待审批申请 | OWNER |
| POST | `/api/groups/{groupId}/join-requests/{requestId}/approve` | 通过申请 | OWNER |
| POST | `/api/groups/{groupId}/join-requests/{requestId}/reject` | 拒绝申请 | OWNER |
| POST | `/api/invitations/{invitationId}/accept` | 接受邀请（成为 MEMBER） | 被邀请者 |
| POST | `/api/invitations/{invitationId}/reject` | 拒绝邀请 | 被邀请者 |
| POST | `/api/invitations/{invitationId}/cancel` | 取消邀请 | 邀请方 |

`GET /api/groups/my` 响应 `data`：

```json
{
  "ownedGroups": [
    { "groupId": 3, "groupCode": "G-ONBOARD", "groupName": "新人入职指南",
      "description": "入职流程…", "pendingRequestCount": 1, "createdAt": "2026-10-16T00:00:00Z" }
  ],
  "joinedGroups": [ { "groupId": 1, "groupCode": "G-RD-TEAM", "groupName": "研发中心知识库", "description": "…" } ],
  "pendingInvitations": [
    { "invitationId": 80, "groupId": 2, "groupName": "产品与运营",
      "inviterUserId": 3, "inviterDisplayName": "李娜", "status": "PENDING" }
  ]
}
```

状态机：邀请 `PENDING → ACCEPTED | REJECTED | CANCELED`；申请 `PENDING → APPROVED | REJECTED`。

## 5. 文档管理 · `/api/documents`

### 5.1 列表 `GET /api/documents`

Query 参数（均可选）：`groupId`、`groupRelation`（OWNER/MEMBER）、`fileName`（模糊）、`uploaderUserId`、`status`（PROCESSING/READY/FAILED）、`uploadedFrom`、`uploadedTo`。

响应 `data: DocumentItem[]`：

```json
[
  {
    "documentId": 101, "groupId": 1,
    "fileName": "后端架构设计说明书.pdf", "fileExt": ".pdf",
    "contentType": "application/pdf", "fileSize": 1863000,
    "status": "READY", "failureReason": null,
    "uploadedAt": "2026-11-03T10:00:00Z",
    "uploaderUserId": 1, "uploaderDisplayName": "系统管理员", "uploaderUserCode": "100001",
    "previewText": "本文档描述…（节选）"
  }
]
```

### 5.2 分片上传（三阶段）

**① 初始化** `POST /api/documents/upload/init`（application/json）：

```json
{
  "groupId": 1,
  "fileName": "年度白皮书.pdf",
  "fileSize": 52428800,
  "contentType": "application/pdf",
  "fileHash": "3f79bb7b435b05321651daefd374cdc681dc06fa…(SHA-256)",
  "chunkSize": 5242880,
  "chunkCount": 10
}
```

响应 `data: UploadInitResult`：

```json
{
  "instantUpload": false,       // true = 秒传成功，documentId 有效，无需继续
  "documentId": null,
  "uploadId": "up_1731650000000_123456",
  "uploadedChunks": [],          // 断点续传：已上传分片序号
  "chunkSize": 5242880,
  "chunkCount": 10
}
```

**② 上传分片** `POST /api/documents/upload/chunks`（multipart/form-data）：
`uploadId` / `chunkIndex`（从 0 起）/ `chunkHash`（分片 SHA-256）/ `chunk`（二进制）。
响应 `data: UploadStatusResult`：

```json
{ "status": "UPLOADING", "uploadedChunks": [0,1,2], "uploadedChunkCount": 3, "chunkCount": 10 }
```

**③ 查询会话状态**（断点续传前调用）`GET /api/documents/upload/{uploadId}` —— 同上结构。

**④ 完成** `POST /api/documents/upload/{uploadId}/complete` → `data: documentId`（触发异步 ETL）。
分片缺失时 success=false，message 指明缺失数量。

### 5.3 小文件直传 `POST /api/documents/upload`（multipart/form-data）

`groupId` + `file`（≤10MB）。响应 `data: documentId`。

### 5.4 预览 / 下载 / 删除 / 重试

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/documents/{documentId}/preview?groupId=` | 返回 `{documentId, groupId, fileName, previewText, status}`；非 READY 拒绝 |
| GET | `/api/documents/{documentId}/download?groupId=` | 二进制流，`Content-Disposition: attachment` |
| DELETE | `/api/documents/{documentId}?groupId=` | 软删除（级联清理向量与 ES 索引） |
| POST | `/api/documents/{documentId}/retry-ingestion?groupId=` | FAILED → PROCESSING 重新入队 |

以上均要求当前用户为目标群组成员；删除/重试要求 OWNER。

## 6. 知识库问答 · `/api/qa`

### 6.1 同步问答 `POST /api/qa/ask`（裸返回）

请求：`{ "groupId": 1, "question": "文档上传流程是什么？" }`

成功回答：

```json
{
  "answered": true,
  "answer": "文档上传流程分为三个阶段：初始化、分片上传、完成合并……",
  "reasonCode": null,
  "reasonMessage": null,
  "citations": [
    { "documentId": 101, "chunkId": 15, "chunkIndex": 3, "fileName": "后端架构设计说明书.pdf",
      "score": 0.94, "snippet": "分片上传协议：init → chunk → complete……" }
  ],
  "evidenceOverview": {
    "documentCount": 2, "evidenceCount": 3, "coverageMode": "MULTI_DOC",
    "groups": [
      { "documentId": 101, "fileName": "后端架构设计说明书.pdf", "evidenceCount": 2,
        "topScore": 0.94, "retrievalSources": ["HYBRID"],
        "snippets": [ { "evidenceId": "ev-101-1", "chunkId": 15, "chunkIndex": 3,
          "startChunkIndex": 3, "endChunkIndex": 4, "score": 0.94,
          "retrievalSource": "HYBRID", "snippet": "……" } ] }
    ],
    "warnings": []
  },
  "recordId": 42
}
```

拒答（证据不足）：

```json
{ "answered": false, "answer": null,
  "reasonCode": "NO_EVIDENCE", "reasonMessage": "检索到的有效证据不足，暂不回答。",
  "citations": [], "evidenceOverview": null, "recordId": 43 }
```

### 6.2 流式问答 `POST /api/qa/stream-ask`（SSE，裸返回）

请求头：`Content-Type: application/json` + `Authorization: Bearer ...`；请求体同 6.1。
响应为 `text/event-stream`，事件序列：

```
event: token
data: 文本增量片段

event: evidence-overview
data: {"documentCount":2,...}

event: citations
data: [{"documentId":101,...}]

event: record
data: {"recordId":42}

event: error
data: {"message":"流式问答服务内部错误"}
```

- `token` 可能出现多次（打字机渲染）；`citations` / `record` 在结束时各出现一次。
- 前端可随时 `AbortController` 中断。

### 6.3 问答历史 · `/api/qa/records`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/qa/records?groupId=&answered=&page=&pageSize=` | 分页：`{items, total, page, pageSize}`，`items` 含 answerPreview/evidenceLevel/citationCount/latencyMs/createdAt |
| GET | `/api/qa/records/{recordId}` | 详情：完整 answer + citations 快照（含 vector/keyword/hybrid 三路得分）+ tokens 用量 |
| DELETE | `/api/qa/records/{recordId}` | 删除记录（级联引用快照） |

## 7. AI 助手 · `/api/assistant`

### 7.1 会话管理 · `/api/assistant/sessions`

| 方法 | 路径 | 包裹 | 说明 |
|---|---|---|---|
| POST | `/api/assistant/sessions` | ApiResponse | 创建会话，data=详情（title 默认"新会话"） |
| GET | `/api/assistant/sessions` | **裸数组** | 会话列表（按 lastMessageAt 降序）：`[{sessionId,title,lastMessageAt}]` |
| GET | `/api/assistant/sessions/{id}` | **裸对象** | 会话详情：`{sessionId,title,status,lastMessageAt,createdAt}` |
| PATCH | `/api/assistant/sessions/{id}` | ApiResponse | 重命名，body `{ "title": "新标题" }`（≤255 字符） |
| DELETE | `/api/assistant/sessions/{id}` | ApiResponse | 删除会话（级联消息与上下文） |

### 7.2 会话上下文 `GET /api/assistant/sessions/{id}/context?recentLimit=12`（裸对象）

```json
{
  "summaryText": "该会话共 6 条消息，主题：…（LLM 压缩摘要）",
  "recentMessages": [
    { "messageId": 3001, "sessionId": 301, "role": "USER", "toolMode": "KB_SEARCH",
      "groupId": 1, "content": "混合检索的优势？", "structuredPayload": null,
      "createdAt": "2026-11-15T10:00:00Z" }
  ]
}
```

`role`：`USER | ASSISTANT | TOOL`；`toolMode`：`CHAT | KB_SEARCH`。

### 7.3 同步聊天 `POST /api/assistant/chat`（ApiResponse 包裹）

请求：

```json
{ "sessionId": 301, "message": "帮我总结这个知识库的主题", "toolMode": "KB_SEARCH", "groupId": 1 }
```

响应 `data`：

```json
{ "sessionId": 301, "messageId": 3005, "reply": "…Markdown 回答…",
  "toolMode": "KB_SEARCH", "groupId": 1,
  "citations": [ { "documentId": 101, "chunkId": 15, "chunkIndex": 3,
    "fileName": "后端架构设计说明书.pdf", "score": 0.91, "snippet": "…" } ] }
```

### 7.4 流式聊天 `POST /api/assistant/chat/stream`（SSE，裸返回）

请求同 7.3。事件体为 JSON 对象，序列：`start → delta×N → done`（异常时 `error`）：

```
event: start
data: {"event":"start","sessionId":301,"toolMode":"KB_SEARCH","groupId":1,"delta":null,"messageId":null,"reply":null,"citations":[],"error":null}

event: delta
data: {"event":"delta","sessionId":301,"toolMode":"KB_SEARCH","groupId":1,"delta":"混合检索","messageId":null,"reply":null,"citations":[],"error":null}

event: done
data: {"event":"done","sessionId":301,"toolMode":"KB_SEARCH","groupId":1,"delta":null,"messageId":3005,"reply":"完整回答","citations":[...],"error":null}
```

## 8. 使用统计（管理员）· `/api/admin/metrics`

| 方法 | 路径 | 参数 | 说明 |
|---|---|---|---|
| GET | `/api/admin/metrics/overview` | — | 今日指标 + 30 天趋势：`{todayRequests, todayTokens, todayCost, todaySuccessRate, dailyTrend[]}`；`dailyTrend[i] = {date, requests, tokens, cost}` |
| GET | `/api/admin/metrics/platform` | `period=TODAY\|LAST_7_DAYS\|LAST_14_DAYS\|LAST_30_DAYS` | 平台统计：`{totalPromptTokens, totalCompletionTokens, totalTokens, totalCost, totalRequests, successRequests, failedRequests, successRate, avgLatencyMs, avgRpm, avgTpm}` |
| GET | `/api/admin/metrics/user/{userId}` | `period` | 用户维度统计（同上结构） |
| GET | `/api/admin/metrics/group/{groupId}` | `period` | 群组维度统计（同上结构） |
| GET | `/api/admin/metrics/trend` | `period`、`module`（QA/ASSISTANT，可选） | 趋势数组 |
| GET | `/api/admin/metrics/rank/users` | `period`、`limit`（默认 10） | 用户排行：`[{id,name,totalRequests,totalTokens,totalCost}]` |
| GET | `/api/admin/metrics/rank/groups` | `period`、`limit` | 群组排行（同上） |

> 注意：`todaySuccessRate` / `successRate` 为**百分数值**（如 97.1 表示 97.1%），前端直接拼接 `%` 展示。
