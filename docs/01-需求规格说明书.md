## 1. 产品概述

### 1.1 一句话定位

CiteMind = **Citation（引证）+ Mind（心智）**：将企业私有文档转化为可检索、可溯源、可对话的知识资产，
**让每一次提问都有据可查**。

### 1.2 解决的三个核心痛点

| 痛点 | 现状 | CiteMind 的解法 |
|---|---|---|
| 幻觉编造 | 大模型自由发挥，无法验证 | 混合检索 + 四级证据评估 + 引用溯源，证据不足主动拒答 |
| 知识割裂 | 文档散落在网盘/本地，搜不到 | 统一上传 → 解析 → 切片 → 向量化 → 双引擎索引的全链路 |
| 无记忆对话 | 每次提问都要重述背景 | ReactAgent + 三级短期记忆压缩，支持跨轮次上下文对话 |

### 1.3 角色定义

| 角色 | 说明 | 可用功能 |
|---|---|---|
| 系统管理员（ADMIN） | 平台运营者 | 用户管理、使用统计、系统设置 |
| 普通用户（USER） | 知识库使用者 | 协作小组、文档管理、知识库问答、AI 助手、系统设置 |
| 群组管理员（OWNER） | 群组内角色（非系统角色） | 上传/删除文档、邀请成员、审批加入申请、移除成员 |

> 权限规则：ADMIN 与业务角色互斥访问——ADMIN 不能进入业务工作区，USER 不能进入管理区（见路由守卫）。

## 2. 功能需求明细

### R1 · 认证与会话管理（优先级 P0）

**目标**：为全站提供安全的身份认证与令牌续期机制。

| 编号 | 需求 | 说明 | 后端 | 前端 | 联调 |
|---|---|---|---:|---:|---:|
| R1.1 | 用户注册 | 用户名（字母/数字/下划线/短横线）+ 邮箱 + 显示名 + 密码；用户名与邮箱全局唯一；注册成功自动登录 | 0.5 | 0.5 | 0.25 |
| R1.2 | 用户登录 | 支持用户名或邮箱（不区分大小写）+ 密码登录；错误提示不泄露账号是否存在 | 0.5 | 0.5 | 0.25 |
| R1.3 | JWT 双令牌签发 | Access Token（30min，HMAC-SHA256，Authorization: Bearer 头）+ Refresh Token（14 天，httpOnly Cookie + 库存哈希轮换） | 1 | — | — |
| R1.4 | 令牌刷新与轮换 | refresh 接口校验 Cookie 中的 Refresh Token，一次性使用并轮换（旧 token 作废）；竞态下保证一个 refresh 只成功一次 | 1 | 0.5 | 0.25 |
| R1.5 | 登出 | 吊销当前 Refresh Token、清除 Cookie；前端清空本地会话 | 0.25 | 0.25 | — |
| R1.6 | 会话恢复 | 前端启动时静默刷新令牌恢复登录态（bootstrap），失败则引导至登录页 | — | 0.75 | — |
| R1.7 | 密码策略与 BCrypt | 密码强度校验（长度/复杂度）；BCrypt 自适应哈希存储；禁止明文/弱哈希 | 0.5 | — | — |
| R1.8 | 强制改密码拦截 | `must_change_password=true` 的用户登录后强制跳转改密页，未改密前禁止访问其他页面 | 0.5 | 0.5 | 0.25 |
| R1.9 | JWT 认证过滤器 | 请求过滤器解析 Bearer Token，注入当前用户上下文；/api/auth/** 白名单放行 | 0.25 | — | — |
| R1.10 | 开发环境管理员引导 | dev profile 启动时自动创建/重置管理员账号，便于本地联调 | 0.25 | — | — |

**验收标准**：
- [ ] 正确凭证登录返回 `{accessToken, currentUser}`；Refresh Token 以 httpOnly Cookie 下发（JS 不可读）
- [ ] Access Token 过期后前端自动 refresh 成功续期，业务请求无感恢复
- [ ] Refresh Token 使用一次即失效；重放旧 Cookie 刷新返回 401
- [ ] 数据库中仅存储 Refresh Token 的 BCrypt 哈希与 JWT 无法伪造（篡改 payload 后 401）

### R7 · 知识库问答（RAG，优先级 P0 ★核心）

**目标**：基于群组知识库的可信问答：检索 → 评估 → 生成 → 溯源。

| 编号 | 需求 | 说明 | 后端 | 前端 | 联调 |
|---|---|---|---:|---:|---:|
| R7.1 | 查询规划 | LLM 判定 DIRECT / REWRITE / DECOMPOSE 策略；最多 3 条并行子查询 | 1 | — | — |
| R7.2 | 混合检索融合 | 向量 + 关键词双通道 RRF 融合排序；类簇聚合 + 邻居窗口扩展补全上下文 | 1.5 | — | — |
| R7.3 | 四级证据评估 | NONE → WEAK → PARTIAL → SUFFICIENT；不足时拒答（reasonCode=NO_EVIDENCE / LOW_CONFIDENCE） | 1 | 0.5（拒答态渲染） | — |
| R7.4 | 回答生成与引用 | LLM 生成 Markdown 回答；CitationAssembler 组装引用（文档/切片/得分/片段）；证据总览（EvidenceOverview） | 1 | 1（引用栏 + 证据面板渲染） | — |
| R7.5 | 流式问答（SSE） | stream-ask 端点逐 token 推送（event: token/citations/evidence-overview/record/error）；前端打字机渲染 + 可中断 | 1 | 1.5 | 0.5 |
| R7.6 | 问答历史 | 问答记录 + 引用快照落库；分页查询、详情回看、删除 | 1.5 | 1（侧栏历史会话） | 1 |

**验收标准**：
- [ ] 就绪文档可问出带 ≥1 条引用的回答，引用可点击定位来源
- [ ] 无证据问题稳定拒答且不消耗生成 token（拒答路径）
- [ ] SSE 断开（用户中断）不产生半截回答入库；历史记录与实时回答一致

## 3. 非功能需求

| 编号 | 类别 | 需求 |
|---|---|---|
| N1 | 安全 | 密码 BCrypt；Refresh Token httpOnly + 库哈希；群组数据强隔离（SQL/检索双过滤）；越权统一 403；操作留痕 |
| N2 | 性能 | 列表类接口 P95 < 300ms；向量检索 P95 < 500ms（HNSW）；SSE 首 token < 2s |
| N3 | 可用性 | ES/MinIO 缺席时应用可启动并优雅降级；ETL 失败可重试不阻塞上传 |
| N4 | 可维护性 | 统一 ApiResponse 包裹；全局异常映射；模块分层（controller/service/mapper/model）；配置集中（yml + 环境变量） |
| N5 | 可观测 | Knife4j 接口文档（/doc.html）；Actuator 健康端点；结构化日志（logback） |
