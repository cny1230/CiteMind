# CiteMind · 前后端联调规范

> 版本：v1.0 ｜ 适用：CiteMind-backend（Spring Boot 3.5，:10001）× CiteMind-frontend（Vue 3 + Vite，:5173）
>
> 本规范约定两端的"契约边界"：响应结构、认证流转、流式协议、错误处理、环境切换与协作流程。
> 前后端任何一侧修改契约，必须先更新对应文档（本文档 + [02-接口文档](./02-接口文档.md)）再动代码。

---

## 1. 环境与启动

### 1.1 本地端口与代理

| 端 | 地址 | 说明 |
|---|---|---|
| 后端 | http://localhost:10001 | `/doc.html` 为接口文档（Knife4j） |
| 前端 dev | http://localhost:5173 | Vite dev server |
| 前端 → 后端 | `/api/**` | 由 `vite.config.ts` 代理到 `http://localhost:10001`（可用 `VITE_DEV_PROXY_TARGET` 覆盖） |

Vite 代理已针对 SSE 做了特殊处理（禁用缓冲、清理 content-length、`no-transform`），
**不要**修改代理配置的 SSE 分支，否则流式回答会被缓冲成一次性输出，破坏打字机效果。

### 1.2 两种运行模式（重要）

前端支持 **Mock 演示模式** 与 **真实联调模式**，由 `CiteMind-frontend/.env` 控制：

```ini
# 演示模式（默认）：内置 Mock 数据驱动全部页面，无需后端
VITE_API_BASE_URL=/api
VITE_USE_MOCK=true

# 联调模式：请求走真实后端
VITE_USE_MOCK=false
```

| 模式 | 数据来源 | 适用场景 |
|---|---|---|
| Mock（默认） | `src/mock/`（内存演示数据 + SSE 模拟） | 界面预览、演示、UI 开发、面试展示 |
| 真实后端 | CiteMind-backend | 接口联调、集成测试 |

切换后需重启 dev server。Mock 层实现要点：

- 非 SSE 请求：`src/api/http.ts` 安装 axios Mock 适配器（`src/mock/index.ts` 路由表），返回值与真实后端契约逐字段对齐；
- SSE 流（qa/stream-ask、assistant/chat/stream）：在 `api/qa.ts`、`api/assistant.ts` 函数入口分支到 `src/mock/streams.ts`。

**新增接口的同步要求**：后端新增/修改接口时，必须同步更新 ①本文档 ②接口文档 ③前端 api 层 ④Mock 路由表（保持两种模式行为一致）。

## 2. 响应契约

### 2.1 统一包裹 `ApiResponse<T>`

```json
{ "success": true, "data": { }, "message": null }
```

- 后端：所有 Controller 返回 `ApiResponse<T>`；**禁止**裸抛 HTTP 错误表达业务失败。
- 前端：api 层函数负责解包（`unwrapApiResponse`），业务代码只拿 `data`；`success=false` 时抛 `Error(message)`。
- **裸返回例外**（不走包裹）：`qa/ask`、两个 SSE 流、`assistant` 会话列表/详情/上下文、文档下载。清单见接口文档 §0.3，
  前端对应函数注释中也逐个标注。

### 2.2 HTTP 状态码约定

| 码 | 语义 | 前端处理 |
|---|---|---|
| 200 | 成功或业务失败（看 success） | 解包逻辑处理 |
| 401 | 未认证/会话过期 | 清空本地会话 → 跳登录页 |
| 403 | 无权限 | toast 提示"无权限"，不跳转 |
| 404 | 资源不存在 | toast 提示 |
| 500 | 服务器错误 | toast 兜底文案"操作失败" |

> 后端用 `BusinessException`（业务失败，HTTP 200 + success=false）/ `ForbiddenException`(403) / `UnauthorizedException`(401)
> 表达错误，由 `GlobalExceptionHandler` 统一映射；**不要**用 4xx 表达纯业务校验失败。

## 3. 认证与令牌流转

### 3.1 双令牌模型

| 令牌 | 载体 | 有效期 | 存放位置（前端） |
|---|---|---|---|
| Access Token | `Authorization: Bearer <token>` | 30 分钟 | 内存（Pinia auth store），**不落 localStorage** |
| Refresh Token | httpOnly Cookie `CITEMIND_REFRESH_TOKEN` | 14 天 | 浏览器自动携带（`withCredentials: true`），JS 不可读 |

### 3.2 会话生命周期（前端 auth store 的职责）

```
应用启动/路由跳转
   │ bootstrap()
   ├─ 内存有会话？ ── 是 → 直接用
   ├─ 否 → POST /api/auth/refresh
   │        ├─ 200 → setSession(accessToken, currentUser) → 继续
   │        └─ 401 → clearSession() → 访问受保护页时跳 /login
   └─ 请求 401（Access 过期）→ 自动 refresh 一次 → 重放原请求 → 仍失败则登出
```

实现约定：

1. **bootstrap 去重**：并发触发时共享同一个 Promise（避免 refresh 竞态导致 Token 轮换失败）；
2. **refresh 幂等**：后端轮换旧 Token，前端任何时刻只允许一个在途 refresh 请求；
3. **登出**：调用 `/api/auth/logout` 后本地 `clearSession()`（远端失败也要清本地）；
4. **登录跳转**：登录成功后按角色跳转——ADMIN → `/app/admin/users`，USER → `/app/groups`；
   `mustChangePassword=true` 时一律先跳 `/app/settings`。

### 3.3 路由守卫规则（两端共同理解）

| 目标路径 | 未登录 | USER | ADMIN |
|---|---|---|---|
| `/`、`/login` | 可见 | 重定向到角色首页 | 重定向到角色首页 |
| `/app/documents|qa|assistant|groups` | 跳 /login | ✅ | ❌ → /app/admin/users |
| `/app/admin/*` | 跳 /login | ❌ → /app/groups | ✅ |
| `/app/settings` | 跳 /login | ✅ | ✅ |
| 其他 | 404 页 | 404 页 | 404 页 |

## 4. 流式接口协议（SSE）

### 4.1 通用约定

- Content-Type：`text/event-stream`；事件以空行（`\n\n`）分隔；
- 前端统一用 **Fetch + ReadableStream** 消费（不用 EventSource，因为需要 POST body 与 Authorization 头）；
- 中断：前端 `AbortController.abort()` → 后端检测断连停止生成；**中断不算错误**，不落库半截回答；
- 心跳/缓冲：后端对每个事件立即 flush；代理层已禁缓冲（见 §1.1）。

### 4.2 问答流（POST /api/qa/stream-ask）

事件顺序与载荷：

| 顺序 | event | data | 次数 |
|---|---|---|---|
| 1 | `token` | 纯文本增量片段 | N 次 |
| 2 | `evidence-overview` | `EvidenceOverview` JSON | 0~1 次 |
| 3 | `citations` | `CitationItem[]` JSON | 1 次 |
| 4 | `record` | `{"recordId": 42}` | 1 次 |
| 异常 | `error` | `{"message": "..."}` | ≤1 次（此后连接关闭） |

前端回调映射：`onToken`（追加渲染）→ `onEvidenceOverview` → `onCitations` → `onRecord`（写入历史会话 ID）。

### 4.3 助手流（POST /api/assistant/chat/stream）

事件 data 为**完整的 JSON 对象**（与类型 `AssistantChatStreamEvent` 对齐）：

| 顺序 | event | 关键字段 |
|---|---|---|
| 1 | `start` | sessionId / toolMode / groupId |
| 2 | `delta` | delta = 增量文本 |
| 3 | `done` | messageId + reply（完整文本）+ citations |
| 异常 | `error` | error = 描述 |

前端：`done` 的 `reply` **整体替换**流式拼接结果，保证与落库内容一致；`citations` 渲染引用卡。

### 4.4 联调排障清单（SSE 常见问题）

| 现象 | 排查点 |
|---|---|
| 一次性收到全部文本 | 代理缓冲未禁用 / 响应被 gzip（清 content-length） |
| 首 token 迟迟不出 | 后端未 flush；或鉴权失败但返回了错误 JSON（检查 HTTP 状态） |
| 中断后连接仍在生成 | AbortSignal 未透传到后端任务 |
| 刷新后历史与流式不一致 | 前端未用 done.reply 覆盖拼接结果 |

## 5. 错误处理与提示

### 5.1 错误消息提取（前端统一函数）

```ts
import { extractApiError } from '@/api/http'
toast.error(extractApiError(error, '操作失败'))
```

优先级：响应体 `message` → axios 错误消息 → Error.message → 兜底文案。

### 5.2 message 文案约定（后端）

- 面向用户可读（中文），不以堆栈/SQL 细节入 message；
- 业务拒绝用词精确："仅群组管理员可上传文档"、"该用户已是群组成员"；
- 同类校验错误集中在后端做（前端只做体验性预校验，如密码长度、必填）。

## 6. 联调工作流

### 6.1 分支与提交

- 分支：`feat/<模块>-<要点>`（如 `feat/qa-stream-citations`）、`fix/<问题>`、`docs/<主题>`；
- 提交信息：`<type>: <摘要>`（feat / fix / docs / refactor / test / chore），正文说明动机与影响面；
- 一个 PR 聚焦一件事；含接口变更时必须附带文档更新。

### 6.2 联调 Definition of Done

- [ ] 后端：`./mvnw clean compile` 通过；接口在 /doc.html 可手工调试通过；与接口文档一致
- [ ] 前端：`npm run type-check` 通过；Mock 与真实两种模式下页面行为一致
- [ ] 联调：核心路径（正常 + 边界 + 越权）跑通；SSE 中断/重试路径验证
- [ ] 文档：接口文档、本规范涉及段落已更新；Mock 路由表已同步

### 6.3 联调自查清单（按模块）

| 模块 | 必测路径 |
|---|---|
| 认证 | 登录→刷新→登出；Token 过期自动续期；错误密码；禁用账号 |
| 群组 | 创建/邀请/申请/审批全状态机；非成员越权 403 |
| 文档 | 小文件直传 + 大文件分片 + 断点续传 + 秒传；失败重试 |
| 问答 | 正常回答带引用；拒答；流式中断；历史回看一致 |
| 助手 | 双模式切换；流式 done 落库一致；长会话摘要生效 |
| 统计 | 调用问答/助手后统计数字变化；周期切换口径正确 |

---

## 7. 变更管理

1. **契约先行**：接口增删改 → 先改 [02-接口文档](./02-接口文档.md)（评审通过）→ 后端实现 → 前端对齐 → Mock 同步；
2. **破坏性变更**：字段改名/结构变化必须在 PR 标题标注 `[breaking]`，并说明前端适配点；
3. **版本策略**：URL 不带版本号（v1 阶段）；未来不兼容变更以 `/api/v2/...` 前缀并行灰度。
